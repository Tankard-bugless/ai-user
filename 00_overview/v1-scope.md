# V1 范围说明

## 1. 项目定位

本项目建设一套 AI 辅助的用户研究工作流。它将模糊业务需求转化为可执行的研究问题、研究方案、问卷或访谈工具，并将原始证据整理为可追溯的发现、洞察、建议和研究报告。

系统采用多 Agent 协作，但 Agent 之间通过结构化研究产物交接，不通过无边界的自由对话交接。状态机负责流程、版本和审批，专家 Agent 负责需要研究判断的工作。

基金客户研究是 V1 的首个应用场景，不是系统唯一适用场景。

V1 的默认简化主链为：研究需求 → 目标受访者画像 → 问卷 → 匿名答卷 → 分析 → 报告。访谈能力作为可选扩展保留，但不要求每个项目同时运行；受访者招募、联系和名单管理属于外部执行责任。

## 2. V1 目标

V1 必须证明以下能力：

1. 将业务需求转化为明确的待支持决策、研究目标、研究问题和可验证假设。
2. 默认把研究问题转化为可分析的问卷；明确需要探索性材料时才启用访谈扩展。
3. 生成可审核的目标受访者画像、问卷、分析计划和测试材料配置。
4. 检查诱导性、双重问题、逻辑跳转、样本偏差、证据不足、数据隐私和金融表达风险。
5. 将答卷、逐字稿等原始资料转化为有来源定位的证据单元。
6. 按照证据 → 发现 → 洞察 → 建议生成报告，并保留反例、限制和人工审核记录。
7. 在金融用户研究报告中，基于同一证据链形成独立的投资者教育建议板块，说明教育重点、适用范围、时点、形式与效果验证边界。
8. 将研究任务、方法、工具、证据索引、报告和复用模板沉淀为研究资产。
9. 更换 AI 模型、问卷平台、知识库或报告工具时，核心研究对象和流程仍然有效。

## 3. V1 核心用户

- 用户研究人员：定义研究、审核工具、判断证据和发布报告。
- 产品、运营、投教等业务需求方：提出问题、确认待支持决策、使用研究结果。
- 方法或合规审核人员：审核研究设计、材料、数据处理和报告表达。

受访客户和问卷参与者是研究参与者，不是本工作流后台系统的操作用户。

## 4. V1 工作流范围

### 4.1 纳入范围

1. 研究需求接收与澄清。
2. 研究目标、研究问题和假设的形成。
3. 定性、定量或组合研究方案设计。
4. 问卷设计，以及按需启用的访谈提纲设计。
5. 在题目生成后使用已审核金融事实和授权材料复核复杂术语，并可在核心答题后人工增加 IMA 等可选学习链接。
6. 通过人工或外部平台执行研究，并接收 Excel 答卷、逐字稿和访谈记录；外部平台只承担智能发行，Excel 是问卷数据的正式回传载体。
7. 定性编码、基础定量分析、证据整理、洞察、投资者教育建议和报告生成。
8. 研究资产的版本化保存和后续复用。

### 4.2 重点建设

V1 优先深做：

- 研究问题理解。
- 研究方案设计。
- 问卷设计与问卷数据分析；访谈作为可选扩展。
- 研究质量审核。
- 证据到洞察的可追溯链路。
- 一个完整案例的端到端演示。

### 4.3 非重点实现

V1 可以通过人工操作或适配器完成，不要求自建：

- 问卷投放和样本招募平台。
- 受访者筛选、联系、激励、替换和名单核验。
- 录音、转写和会议系统。
- 完整客户数据平台。
- 完整研究资料搜索引擎。
- 复杂可视化前端。

## 5. 研究模板范围

### 5.1 V1 默认模板

- 假设验证型问卷：用于在明确假设和分析计划下收集结构化数据。

### 5.2 可选扩展

- 探索型访谈：只在研究问题无法通过结构化问卷充分回答时启用，用于理解真实行为、动机、决策过程、阻碍和替代方案。
- 人工试答或预测试：不作为问卷生成和 Gate 2 的默认前置条件；高风险、复杂跳转或业务方明确要求时才启用。

### 5.3 V1 工具模式

- 材料理解度测试：作为问卷或访谈的可选模式，测试参与者接触材料后的理解、误解和态度变化。
- IMA 链接是核心答题后的可选学习入口，不构成独立研究主线，也不进入研究证据链。IMA OpenAPI 接口只保留扩展位置，V1 当前不启用。

### 5.4 后续组合模板

- 混合研究：通过组合访谈和问卷模板实现，不在 V1 重复建设一套独立逻辑。

## 6. 明确排除项

V1 不建设或不授权以下能力：

1. 全量客户档案、CRM 或客户数据中台。
2. 自动修改法定风险适当性标签。
3. 根据一次研究自动生成正式客户标签。
4. 自动发布问卷、自动联系客户或自动发送外部材料。
5. 自动决定基金产品设计、营销策略或客户投资方案。
6. 将小样本定性结果外推为市场规模或客户总体比例。
7. 将模拟用户、AI 角色或示例数据当作真实客户证据。
8. 把 IMA 当作用户信息库、用户行为追踪工具或自动化研究证据来源；当前仅将其视为可选的官方知识入口。
9. 自动挑选、招募、核验、联系或替换受访者；系统只定义目标受访者画像。

## 7. 核心边界

### 7.1 研究建议与业务决策

研究系统输出建议，业务负责人作出决策。报告必须区分 Recommendation 与 Business Decision。

### 7.2 研究分群与客户标签

单个项目可以形成研究分群、候选画像或候选研究标签，但不得自动写入正式客户档案。正式标签需要独立治理规则、充分证据和人工审批。

### 7.3 研究证据与客户事实

研究参与者的一次回答只是在特定研究情境下的证据，不能自动升级为长期稳定的客户事实。

### 7.4 IMA

IMA 的 V1 角色是可选学习资源。当前验证表明，订阅知识库完整正文阅读和问答依赖 IMA 等腾讯侧产品环境，在当前 Codex 工作流中不具备可迁移调用条件，因此 `ima_api_status=RESERVED_DISABLED`。CAP-03 不把 IMA API 作为题目生成或知识复核步骤；金融事实由适用事实库、监管文件和产品法律文件确定。研究人员仍可人工加入已审核知识库入口，不记录点击、停留或身份关联。未来接口满足跨环境正文读取、来源追溯、安全测试和人工批准条件后，通过新版本启用。

### 7.5 平台与核心逻辑

ResearchBrief、ResearchPlan、InstrumentSpec 等核心产物使用平台无关格式。SurveyKing 或其他平台通过 Adapter 接收转换后的数据。

腾讯问卷等平台只负责智能发行、回收和导出。分析阶段不依赖平台答案 API 或在线统计；业务方回传的 Excel 经字段映射、脱敏和质量检查后进入 FieldworkPackage。

### 7.6 投资者教育建议

投资者教育建议是 Recommendation 的一个行动领域，不是新增研究主线。它必须由本轮 Finding 和 Insight 推导，回答“需要解释什么、面向谁、何时解释、用什么候选形式、如何验证效果”。问卷中的内容、形式或时点偏好不能单独证明投教有效，也不得据此生成产品推荐、适当性判断或收益暗示。

## 8. 强制设计原则

1. 产物驱动：正式交接依赖 Artifact，不依赖聊天历史。
2. 专家模块化：每个专家有明确输入、输出、判断权和禁止事项。
3. 人工最终审批：AI 可以预审和建议，不能独立通过四个正式 Gate。
4. 证据可追溯：发现、洞察和建议必须回溯到证据单元及原始资料位置。
5. 版本不可变：被批准的产物版本冻结，修改产生新版本。
6. 最小数据使用：Agent 只读取完成当前任务所必需的数据。
7. 默认脱敏：进入分析和多 Agent 流转前，参与者信息原则上使用编号。
8. 适配器隔离：外部平台能力不得渗入核心研究 Schema。
9. 示例隔离：示例、模拟和测试数据必须显著标识，不得进入正式证据。
10. 反例保留：不同声音和矛盾证据不得被静默删除。

## 9. V1 完成标准

V1 被视为完成，需要同时满足：

- 核心标准文件形成批准版本。
- 八类核心研究/治理产物具有可校验的 Schema 或明确结构。
- 六个专家具有完整能力卡和可复用测试案例。
- 四个 Gate 能够批准、退回、拒绝并记录原因。
- 至少一个真实或经过明确脱敏的案例跑通完整产物链。
- 案例中至少展示一次质量审核退回和修订。
- 任意一条报告建议可以追溯到研究问题、证据和原始资料位置。
- 至少完成一种问卷平台格式转换或可验证的模拟转换。
- 答辩材料能够解释系统边界、可迁移性和人工责任。

## 10. 当前未决但不阻塞的问题

- 第一个演示案例的最终题目。
- SurveyKing 是否作为首个真实适配器。
- 最终演示采用文档、表格工作台还是轻量网页。
- 正式客户标签的跨项目升级机制。
- 生产环境的细粒度访问控制实现。

这些问题将在相应里程碑解决，不应阻塞范围和基础口径的冻结。
