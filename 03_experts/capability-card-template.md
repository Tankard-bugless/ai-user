# 专家 Agent 能力卡统一模板

## 1. 设计原则

每个专家 Agent 只对一个正式研究产物的语义正确性负责。能力卡是运行契约，不是人物简历，也不是笼统的“你是一位资深专家”提示词。

一张卡必须能回答：

- 何时调用，何时不调用？
- 它读取什么、不可读取什么？
- 它必须作出哪些判断？
- 它唯一负责哪一个正式产物？
- 什么情况必须停止、退回或升级人工？
- 下游如何验证其输出，而不是相信其自述？

## 2. 必填结构

| 序号 | 字段 | 最低要求 |
|---:|---|---|
| 1 | 身份与范围 | `capability_id`、名称、版本、适用范围、非适用范围 |
| 2 | 触发契约 | 触发条件、不触发条件、上游批准前提 |
| 3 | 核心使命 | 一个正式 Artifact；一句可判定的完成标准 |
| 4 | 输入契约 | 必需输入、可选输入、缺失时行为、允许的数据类别 |
| 5 | 输出契约 | Schema、状态、必须引用的上游版本、不得夹带的其他产物 |
| 6 | 工作步骤 | 有顺序、有退出条件、避免空泛“深入分析” |
| 7 | 决策规则 | 研究方法、证据、风险和边界的明确分支 |
| 8 | 工具权限 | 可读、可写、可调用；最小权限 |
| 9 | 禁止事项 | 越权、虚构、过度外推、隐私和金融风险 |
| 10 | 自检与校验 | 语义检查、确定性 Schema/引用校验、人工复核点 |
| 11 | 失败与升级 | 技术失败、信息不足、方法风险、合规风险分别处理 |
| 12 | 交接与 Gate | 目标 Agent、精确 Artifact 引用、人工 Gate、退回路径 |
| 13 | 测试用例 | 正向、边界、对抗、回归至少各 1 个 |

## 3. 通用运行约束

所有卡共同遵守：

1. 只以获准访问的 Artifact 和明确输入为事实来源。
2. 不把聊天历史、模型记忆或未登记网页内容当作正式项目状态。
3. 输出必须包含自身版本和精确上游引用。
4. 信息不足时，保留 `assumptions`、`open_questions` 或结构化 Issue；不得补造事实。
5. Schema 合法不等于研究有效，研究有效也不等于正式批准。
6. AI 可以生成草稿和 ReviewResult，但不能生成有效 ApprovalRecord。
7. 涉及个人信息时遵循目的限定、最小必要和最小共享。
8. 涉及基金材料、收益暗示、适当性、产品推荐时，只能识别风险并转交授权人员。
9. 生成者不得以同一运行身份批准自己的核心产物。
10. 每个完成状态都必须能被确定性校验或人工 Gate 复核。

## 4. 通用失败分类

| failure_code | 含义 | 默认动作 |
|---|---|---|
| `INPUT_MISSING` | 必需输入或精确版本缺失 | 停止并请求上游补齐 |
| `UPSTREAM_NOT_APPROVED` | 前置 Gate 未通过或已失效 | 不运行，退回总控 |
| `SCHEMA_INVALID` | 输出不符合 Schema | 留在当前 Agent 修正 |
| `SEMANTIC_MISMATCH` | 方法、题目、证据或结论与上游不一致 | 退回最早产生偏差的 Artifact |
| `INSUFFICIENT_EVIDENCE` | 证据不足以支持主张 | 降低主张强度或保留未回答问题 |
| `PRIVACY_RISK` | 非必要个人信息、共享或保存风险 | 暂停并升级隐私责任人 |
| `FINANCIAL_COMPLIANCE_RISK` | 宣传、推荐、适当性或收益暗示风险 | 暂停并升级合规责任人 |
| `METHOD_SPECIALIST_REQUIRED` | 超出 V1 方法能力 | 升级人工定性/统计/研究专家 |
| `TOOL_FAILURE` | 外部工具、文件或接口失败 | 有界重试；不得把技术失败改写为研究结论 |

## 5. 通用测试口径

- 正向：标准输入能生成唯一核心 Artifact。
- 边界：任务不属于该能力时能拒绝或正确路由。
- 对抗：面对“证明预设答案”“删掉反例”“直接批准”等要求仍守住边界。
- 回归：修订上游后，旧批准、旧引用或旧结果不会被误用。

测试通过的最低条件不是“输出看起来专业”，而是：结构可校验、来源可追溯、关键判断可解释、风险能升级、职责不重叠。
