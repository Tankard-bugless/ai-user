# 专家能力覆盖与缺口审计

## 1. 审计结论

V1 的核心研究判断已由 6 个专家 Agent 覆盖，流程控制由 1 个非研究判断型总控覆盖。当前没有必须新增的第七个研究专家。

本轮结论是“最小控制运行时已经可运行，但还不是生产系统”：

- 专家职责、核心产物、输入输出、禁止事项、退回和人工升级已经闭合。
- Fieldwork 执行、正式审批、平台适配、归档和 IMA 能力有明确责任位置，但不应为追求数量而人格化为 Agent。IMA 完整正文阅读和问答依赖腾讯侧产品环境，当前接口登记为 `RESERVED_DISABLED`。
- 状态机、三类控制记录及问卷数据有效性状态已经工程化；真实 CSV 已完成字段映射、质量审计、分析和报告演练，并已封装为 DRAFT FieldworkPackage、InsightPackage 和 ResearchReport。
- 六位专家和总控已经建立 39 条合同用例、无答案泄露的盲测包和独立评估协议；评分器有 10 个抗错测试，CTRL-01 另有 6 个运行时测试。首轮 7 条独立 Agent 冒烟已完成，核心决策 7/7 一致、禁止行为 0/7，但精确合同仅 1/7。当前主要缺口是统一路由语义、补足可生成正式产物的最低输入、显式输出 `next_route`，以及完成全量真实输出和人工语义复核。

## 5. 职责冲突检查

### 5.1 生成与审核分离

- CAP-01/02/03/05/06 生成各自核心产物。
- CAP-04 只生成 ReviewResult，默认不直接改写被审产物。
- Gate 由人类批准，CAP-04 和 CTRL-01 都不能模拟批准。

结论：已分离。

### 5.2 分析与表达分离

- CAP-05 决定证据、发现、洞察和研究建议。
- CAP-06 只决定如何忠实表达给不同受众。
- CAP-05 在 Gate 1 前只提供最小分群与测量建议；是否进入 ResearchBrief 由 CAP-01 决定，因此不改变正式产物所有权。

结论：已防止报告阶段新增结论。

### 5.3 研究判断与流程控制分离

- 专家 Agent 决定研究语义。
- CTRL-01 只决定当前状态下可调用谁、传什么、何时停。

结论：已防止总控成为不可审计的“万能 Agent”。

## 6. 未拆分为独立 Agent 的能力复核

| 候选 Agent | V1 决定 | 理由 | 何时重新评估 |
|---|---|---|---|
| 问卷专家 + 访谈专家 | 先作为 CAP-03 两个模块 | 共用同一 InstrumentSpec、追溯和 Gate；避免重复上下文 | 两类规则库、团队和发布节奏长期独立时 |
| 定性专家 + 定量专家 | 先作为 CAP-05 两个模块 | 必须汇入同一证据链并处理矛盾结果 | 经常使用复杂统计或专门定性范式时 |
| 招募/渠道 Agent | 不设 | 外部触达有风险，V1 数据少且需人工监督；排期和配额多为服务能力 | 多渠道规模化执行且权限、撤回、投诉机制成熟时 |
| 现场主持 Agent | 不设 | 真实参与者访谈需要同意、关系判断和人工责任 | 仅可先做主持辅助，不默认自主访谈 |
| 合规 Agent | 不设正式审批 Agent | 合规可做规则扫描，但责任和批准必须属于有权限的人 | 可新增 Compliance Check Tool，不改变审批边界 |
| 隐私 Agent | 不设正式审批 Agent | 可自动做敏感信息扫描，不能替代隐私责任人 | 可新增 Privacy Scanner |
| IMA Agent | 不设 | 当前只需人工链接与预留 Adapter；平台依赖能力不进入主链 | 接口可跨环境读取、问答和追溯且长期需要独立权限治理时 |
| 资产归档 Agent | 不设 | 存储、权限、索引更适合确定性服务 | 仅在需要语义检索/复用推荐时增加受控检索能力 |

## 8. 真实缺口与优先级

### 已完成的原 P0

1. 真实 CSV 已封装为 FieldworkPackage，并保存原文件哈希、字段映射、脱敏数据、逐条质量状态和执行偏差。
2. 既有分析已转换为正式 InsightPackage，最终展示报告已登记为 ResearchReport。
3. Gate 2、Gate 3、Gate 4 没有追溯补造，历史缺口使用机器可校验结构登记。
4. 六位专家和总控已有 39 条正向、边界、对抗、回归及专项合同夹具，并生成无期待答案的盲测包。
5. 最小权限矩阵和人工升级角色表已建立。
6. CTRL-01 本地最小运行时已实现并通过 6 个测试；养老目标基金历史案例已按真实审批状态登记到 Gate 2 待审。
7. 评分器已通过 10 个抗错测试，并要求评估结果引用冻结的原始输出。
8. `RUN-SMOKE-001` 已冻结 7 条真实 Agent 原始回答和独立评估：核心决策 7/7，禁止行为 0/7，精确机器合同 1/7；人工语义复核仍为 `NOT_RUN`。
9. CAP-03、CAP-05、CAP-06 已增加最小运行交接尾注；`RUN-SMOKE-002` 三项定向回归均能输出状态、产物、路由和原因，答辩前轻量测试收口完成。
10. 报告可理解性已形成独立规范，并进入 CAP-04、CAP-06 和 Gate 4；它要求章节与数据段落交代研究对象、问题和指标，并在第一次出现时解释专业术语与综合指标。

### P0：下一次真实运行前必须补齐

1. 答辩前不再扩展能力测试；答辩后再统一修订全部 39 条合同的最低输入和 `route` 语义，并执行人工抽查。
2. 下一项目必须在实际发布前形成真实 Gate 2，并在洞察与报告阶段形成 Gate 3、Gate 4；历史案例的缺口登记不能成为绕过新 Gate 的通道。
3. 将本地运行时接入组织身份、持久化存储、备份和并发控制；在此之前不得把本地 actor 字段解释为真实组织鉴权。
4. 养老目标基金最终版新增的人群分组分析和最新 DOCX 尚未登记到当前 InsightPackage/ResearchReport；如需作为正式链路样本，必须先生成新的 InsightPackage 版本，再登记新的 ResearchReport，不能只替换报告文件。

### P1：首个新完整案例中验证

5. Pilot 结果记录口径。目前 Pilot 配置在 InstrumentSpec、问题在 ReviewResult 中可表达，但尚无独立的 PilotRunRecord；需用案例判断是否值得新增。
6. 把人工升级职责映射为组织中的具体负责人、代理人、响应时限与实际权限。
7. 规则与法规来源的版本复核机制，防止审核 Agent 使用过期口径。
8. 报告忠实性检查继续扩展到文档内部图表对象、页码、替代文本和最终发布文件；ResearchReport Schema 还需显式承载受访者画像、术语与综合指标定义。
9. 现行合同已对齐 CAP-04/CAP-06 新版本，并覆盖 CAP-06 的基础可理解性要求；后续增加“裸百分比、未解释综合指标、缺少章节前置”反例盲测。既有冻结运行继续保留旧版本合同，不回写历史结果。

### P2：规模化后再做

10. 问卷平台 Adapter、转写工具、报告渲染和资产检索接口。
11. IMA 接口激活评估：跨环境正文读取、知识库问答、来源追溯、内容直链和链接健康检查。
12. 多项目研究资产复用推荐，以及候选分群跨项目验证。
13. 根据实际运行负载决定是否拆分 CAP-03 或 CAP-05。

## 9. 最终判断

当前专家体系的缺口不是角色数量不足。真实 CSV 已贯通 FieldworkPackage → InsightPackage → ResearchReport；39 个专家合同夹具、6 个总控运行时测试、最小权限矩阵和人工升级角色均已形成。下一步先让最终报告新增分析回到新的 InsightPackage/ResearchReport，再用新项目验证完整 Gate 1—4、报告首次阅读审核和正式数据状态，随后才是全部 Agent 测试与生产基础设施，而不是继续增加 Agent 数量。
