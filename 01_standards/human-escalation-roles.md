# 人工升级角色表

## 1. 角色定义

这里定义的是职责角色，不预设具体姓名。正式部署时，组织必须为每个角色登记负责人、代理人、可审批 Gate、可访问数据范围和响应时限。

| 角色 | 负责判断 | 不应被要求承担 |
|---|---|---|
| 研究负责人 | 研究问题、方法边界、证据质量、研究结论是否可提交 Gate | 代替业务负责人决定产品是否上线 |
| 业务决策负责人 | 研究用途、优先级、资源投入与建议是否转化为业务行动 | 改写数据或要求删除不利证据 |
| 数据质量负责人 | 字段映射、答卷状态、排除口径、分母、敏感性与统计复核 | 在没有权限时读取联系方式映射 |
| 数据与隐私责任人 | 数据最小化、同意、去标识化、访问、保留、撤回与删除 | 判断研究结论是否“好看” |
| 金融事实责任人 | 产品事实、份额类别、风险表述、适用范围和来源版本 | 替代研究人员判断题目是否中立 |
| 合规/法务责任人 | 宣传边界、适当性、收益与风险表达、对外分发要求 | 把合规通过解释为研究方法有效 |
| 定量方法专家 | 抽样、权重、显著性、多变量模型、信效度和复杂因果问题 | 为小样本或便利样本背书总体代表性 |
| 定性方法专家 | 访谈招募、主持、编码、一致性、反例与饱和边界 | 把个案直接升级为普遍结论 |
| 发行与渠道负责人 | 问卷/访谈实际触达、渠道配置、暂停回收与平台权限 | 未经 Gate 2 自行改题或发布 |
| 报告分发负责人 | 内部/外部受众、渠道、版本和访问控制 | 在没有 Gate 4 时扩大分享范围 |
| 信息安全/平台负责人 | 密钥、接口、故障、审计、安全事件和供应商权限 | 对研究语义内容作最终判断 |

## 2. Gate 的最小人工角色

| Gate | 必需角色 | 条件性加入 | 批准对象 |
|---|---|---|---|
| Gate 1 问题确认 | 研究负责人、业务决策负责人 | 数据与隐私责任人（计划使用新敏感数据时） | ResearchBrief 精确版本 |
| Gate 2 执行放行 | 研究负责人、发行与渠道负责人 | 金融事实责任人、合规/法务、数据与隐私责任人、定量/定性方法专家 | ResearchPlan、全部执行用 InstrumentSpec 与必要 ReviewResult 的精确组合 |
| Gate 3 证据审核 | 研究负责人、数据质量负责人 | 定量方法专家、定性方法专家、金融事实责任人 | InsightPackage 精确版本及分析边界 |
| Gate 4 报告/分发 | 研究负责人、报告分发负责人、业务决策负责人 | 合规/法务、数据与隐私责任人、金融事实责任人 | ResearchReport 精确版本和明确分发范围 |

CAP-04 可以准备审核意见，但不能替代上表中的人类批准。某角色“参与讨论”也不等于已经批准，正式决定必须写入 ApprovalRecord。

## 3. 升级触发与暂停条件

| 触发事件 | 先暂停什么 | 主责任角色 | 恢复条件 |
|---|---|---|---|
| 研究目标要求证明预设答案或删除反例 | 当前语义产物提交 | 研究负责人、业务决策负责人 | 改为中性可证伪问题并记录冲突处理 |
| 出现收益保证、适当性、产品推荐或错误金融事实 | 相关题目、材料和报告段落 | 金融事实责任人、合规/法务 | 适用来源和措辞审核完成，问题关闭 |
| 新增姓名、联系方式、账户、交易截图或其他敏感数据 | 采集、导入和 Agent 访问 | 数据与隐私责任人 | 用途、最小化、同意、访问和保留规则获批 |
| 样本不足却要求总体比例、显著性或因果结论 | 相应结论和图表 | 定量方法专家、研究负责人 | 改写边界或补充足以支持推断的设计 |
| 单个强烈个案被要求写成普遍洞察 | Finding/Insight 提交 | 定性方法专家、研究负责人 | 降级为个案证据或补充验证 |
| 数据集存在未解决 REVIEW_REQUIRED 或分母不一致 | 分析与报告生成 | 数据质量负责人 | 逐条状态解决，或以正式例外和明确限制获准 |
| Gate 版本与当前 Artifact 不一致 | 所有下游迁移 | 研究总控、对应 Gate 审批人 | 新版本重新审核并形成新的 ApprovalRecord |
| IMA 接口不可用却被要求声称已检索事实 | IMA 事实引用 | 金融事实责任人、平台负责人 | 使用已审核替代来源，或接口真实启用并留存可验证记录 |
| 外部工具失败、密钥异常或疑似数据泄露 | 相关 Adapter 与外部写入 | 信息安全/平台负责人 | 事件关闭、权限轮换、影响确认和恢复批准 |
| 报告拟扩大到新受众或外部发布 | 发送、公开链接与文件复制 | 报告分发负责人、合规/法务 | Gate 4 对精确版本和新范围批准 |

## 4. 严重度与响应

- `BLOCKER`：立即进入 `PAUSED_RISK`，不得靠重试绕过；由有权限角色决定继续、修改或取消。
- `MAJOR`：退回最早责任 Artifact；修复后必须重新审核受影响版本。
- `MINOR`：可在当前阶段修复，但关闭问题时必须保留前后版本和验证记录。
- 技术失败：只允许有界重试；超过阈值转给平台负责人，不把技术失败伪装成语义通过。

## 5. 养老目标基金案例的真实历史状态

本案例只有 Gate 1 的正式记录。Gate 2、Gate 3、Gate 4 当时均未形成 ApprovalRecord，因此：

- 不追溯补造任何人的批准；
- FieldworkPackage、InsightPackage 与 ResearchReport 均登记为 `DRAFT`；
- 可以用于内部复盘和答辩演示；
- 若以后需要正式外发，应由当前责任角色针对当前精确版本重新审核，而不是把历史讨论解释为批准。
