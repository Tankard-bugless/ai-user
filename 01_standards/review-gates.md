# 四个人工审核关口

本文件是项目内审核关口的唯一权威版本。研究方案确认并入 Gate 2，不再维护五关口和四关口两套并行口径。

## 1. 全局规则

1. AI 专家可以执行预审、发现问题并给出建议状态，但不能完成正式批准。
2. 正式批准必须由授权人员针对明确的 Artifact ID 和版本作出。
3. Approval Record 与被审核产物分开保存；不得通过修改已批准产物中的状态字段来伪造新审批。
4. 产物一经批准即冻结。任何内容修改都产生新版本，并重新进入相应 Gate。
5. 审核人员不得只看到摘要；必须能访问上游产物、主要证据和变更记录。
6. 所有退回和拒绝必须记录原因、责任人、目标阶段和必须修改项。
7. Gate 只判断是否允许进入下一阶段，不代替日常质量检查。

## 2. 统一审核状态

| 状态 | 含义 | 是否可继续 |
|---|---|---|
| PENDING | 等待授权人员审核 | 否 |
| APPROVED | 指定版本通过审核 | 是 |
| CHANGES_REQUIRED | 方向可继续，但必须修改并提交新版本 | 否 |
| REJECTED | 当前方案不应继续，需要重新定义或终止 | 否 |
| CANCELLED | 项目或审批由有权限人员取消 | 否 |

## 3. Gate 1：研究问题确认

### 目的

防止业务愿望、既定答案或模糊现象直接进入研究设计。

### 必需输入

- ResearchBrief
- 原始业务需求记录
- 必要的产品或业务背景
- 数据敏感性初步判断

### 自动校验

- 必填字段、ID 和版本完整。
- 至少存在一个明确的 Supported Decision。
- Research Objective、Research Question 与 Hypothesis 类型分离。
- 假设具有可证伪条件，不被标为事实。
- 范围、目标参与者和排除项已说明。
- 新建或实质修订的问卷项目已定义一个主要分群、拟比较结果、测量维度和分析边界。
- 每项拟比较都引用现有 Research Question，主要分群类别不重复。
- 不包含已经写好的问卷题目或预设结论。

### AI 预审重点

- 研究问题能否真正支持待支持决策。
- 是否遗漏合理替代解释。
- 是否出现确认偏误、营销目标伪装成研究目标或金融收益暗示。
- 是否请求了超出研究所需的客户敏感数据。
- 分群信息是否确实服务研究问题，而不是因“以后也许有用”而收集。
- 预分析建议是否被误写成已经观察到的用户差异。

### 人工审批角色

- 研究负责人
- 业务需求方或决策代表
- 涉及敏感金融表达或数据时的合规代表

### 通过条件

- 待支持决策、研究目标和研究问题一致。
- 需求方确认研究方向没有被错误转译。
- 假设覆盖主要解释但未被写成既定答案。
- 数据使用范围合理。
- 问卷项目的主要分群、比较用途与最小数据需求已确认；具体题干和编码留待 Gate 2。

### 退回目标

ResearchBrief 生成阶段。

## 4. Gate 2：研究方案与工具确认

### 目的

确认研究方法、目标受访者画像、问卷或访谈工具、测试材料和分析流程能够有效且合规地回答研究问题。系统不审核业务方如何寻找和联系受访者。

### 必需输入

- Gate 1 的 APPROVED 记录
- ResearchPlan
- InstrumentSpec
- ReviewResult
- 所有测试材料及其版本
- 涉及金融事实时：适用金融事实库的精确版本和本轮金融事实审核记录
- 使用 AI 解释时：解释文本、事实来源及其展示位置
- 人工加入 IMA 学习链接时：资源记录及链接审核状态

如项目主动采用人工试答或预测试，可附对应记录；它不是默认必需输入。

### 自动校验

- 每个研究问题都有对应方法和分析计划。
- 每个核心题目或访谈模块关联研究问题或假设。
- Gate 1 的测量维度和拟比较结果均能映射到计划变量与工具题目。
- 每条可判断真假的金融陈述均关联已验证 `fact_id`；动态产品事实包含当前产品法律文件来源和日期。
- 问卷题号、选项、跳转、终止、必答和配额逻辑有效。
- 每个问卷变量已定义正常值、特殊值、结构性空缺和题目缺失；问卷级硬排除与复核信号使用统一状态和原因码。
- 知识题答错或选择“不确定”、画像题选择“不愿回答”不会被自动判为无效答卷。
- 量表方向和锚点一致；五点程度量表的中点不承担“不知道/不适用”含义。
- 访谈时长与模块估时不冲突。
- 测试材料具有 material_id、版本和展示位置。
- `ima_api_status=RESERVED_DISABLED`，InstrumentSpec 不依赖 IMA OpenAPI 搜索、正文读取或知识库问答。
- 客观知识、辨识或理解题的 AI 解释不得在回答前泄露答案；解释不写进选项。
- 人工加入的 IMA 等学习资源明确标记为可选入口和“非研究证据”；V1 不要求点击或停留追踪。
- 参与同意、录音说明、脱敏和数据保存规则存在。

### AI 预审重点

- 方法是否适配研究问题，而不是习惯性选择问卷或访谈。
- 是否存在诱导题、双重问题、抽象回忆、社会期望偏差或选项不完整。
- 题型是否适合测量目的，是否为了“丰富题型”而无必要地加入排序或矩阵。
- 是否把材料理解、产品吸引力、购买意向和风险承受能力混为一项指标。
- 是否把客观知识、主观了解程度和实际行为混为同一指标。
- 是否混淆 FOF、养老目标基金、个人养老金可投基金、账户和份额类别。
- 是否把通用监管事实误写成所有产品都相同，或使用已经过期的费率、持有期、名录和下滑曲线。
- 是否在接口未启用时调用 IMA、伪造 IMA 正文或把接口设为问卷生成的必需依赖。
- AI 解释是否确有必要、语言通俗且非推荐性，展示时点是否污染原始认知测量。
- 是否包含收益承诺、产品推荐或其他可能引发金融合规风险的表述。
- 目标受访者画像是否与研究问题相关，且包含必要的行为、经验或决策角色。
- 分析计划是否在数据收集前足够明确。

### 人工审批角色

- 研究负责人或方法审核人员
- 问卷或访谈执行负责人
- 必要时的合规、法务或数据保护人员

### 通过条件

- ResearchPlan 与 InstrumentSpec 能共同回答已批准的研究问题。
- ReviewResult 中不存在未解决的阻断问题。
- 问卷结构、题目追溯、选项、跳转、变量和分析口径已通过自动检查与研究人员审核。
- 单份答卷 `VALID/REVIEW_REQUIRED/EXCLUDED` 与整体数据集输出状态已在采集前定义，平台转换不改变其语义。
- 金融事实审核不存在未关闭的 `REVISE` 或 `ESCALATE`；知识题标准答案均有可核验来源。
- AI 解释的事实来源与展示时点已审核；IMA 接口保持未启用，人工学习链接不进入证据链。
- 外部发布材料和数据处理方式已获批准。

### 退回目标

- 方法或目标受访者画像问题：ResearchPlan 阶段。
- 题目、提纲、材料或逻辑问题：InstrumentSpec 阶段。

## 5. Gate 3：证据与洞察确认

### 目的

防止证据不足、错误统计、断章取义或过度外推被升级为正式洞察。

### 必需输入

- FieldworkPackage 清单
- 数据质量与样本完成说明
- 分析过程记录、代码本或统计说明
- InsightPackage
- 证据等级和置信度判断

### 自动校验

- 每个 Finding 引用 Evidence Unit。
- 每个 Insight 引用 Finding。
- 每个 Recommendation 引用 Insight。
- 每个 Recommendation 标明行动领域；`INVESTOR_EDUCATION` 建议包含学习缺口、适用范围、内容、时点、形式、边界和效果验证。
- 定量比例包含分子、分母、题目 ID 和筛选条件。
- 定性原话包含参与者编号和来源定位。
- 反例、缺失值、无效样本和研究限制字段存在。
- 所有记录已完成状态判定，不存在未解决的 `UNASSESSED` 或 `REVIEW_REQUIRED`；整体数据集状态为 `ANALYSIS_READY` 或 `ANALYSIS_READY_WITH_LIMITS`。
- 知识题正确、错误与不确定分别报告；结构性空缺、题目缺失和不适用使用不同口径。
- 候选研究标签没有被标为正式客户标签。

### AI 预审重点

- 发现是否仅描述本样本，而未虚假外推总体。
- 洞察是否有清晰推理并考虑替代解释。
- 是否把单个参与者意见写成共同规律。
- 是否遗漏与主要模式矛盾的证据。
- 置信度是否符合证据质量，而非由模型任意给出。
- AI 生成的编码或总结是否经过人工抽查。
- 是否把内容、形式或时点偏好误写为已验证的投教效果，或用通用科普填补证据不足。

### 人工审批角色

- 研究负责人
- 负责该项目分析的研究人员
- 必要时的数据分析或方法专家

### 通过条件

- 证据链完整且能够复核。
- 发现、洞察和建议的语义层级正确。
- 重要反例和限制已呈现。
- 候选分群和标签没有越权升级。
- 投资者教育建议与本轮证据强度一致，不包含产品推荐、收益暗示或适当性判断。

### 退回目标

- 数据质量或来源问题：FieldworkPackage 整理阶段。
- 编码、统计或解释问题：InsightPackage 分析阶段。

## 6. Gate 4：报告发布与归档确认

### 目的

确认正式报告忠实表达研究结果，并明确哪些内容可以归档、共享或形成后续行动。

### 必需输入

- Gate 3 的 APPROVED 记录
- ResearchReport
- 最终 InsightPackage
- 报告使用的图表和证据引用清单
- 报告中专业术语、综合指标与分群口径的首次出现说明
- 研究限制和未回答问题
- 归档清单及数据敏感性说明

### 自动校验

- 报告中的每项建议能够追溯到 Insight 和 Finding。
- 报告中的数字与 InsightPackage 一致。
- 附件、图表、链接和版本引用有效。
- 报告不包含未授权的个人身份和敏感金融信息。
- Business Decision 与 Recommendation 明确分离。
- 未将候选研究标签写成正式客户事实。
- 投资者教育板块只引用上游 `INVESTOR_EDUCATION` 建议；无证据时明确标为不适用。
- 总览页和各分析章节在进入数字前已说明研究对象、研究问题、样本或筛选范围。
- 专业术语与综合指标第一次出现时已解释含义、组成或计算方式，不能假设读者看过问卷。
- 核心数据段落不存在无先行词的“该组”“四道题”“这一结果”或裸百分比结论。

### AI 预审重点

- 报告是否夸大结论或隐藏限制。
- 执行摘要是否与正文证据一致。
- 建议是否具体但没有越权替业务方作出决定。
- 是否存在营销化、收益暗示或不恰当客户分类表达。
- 投资者教育板块是否回应知识缺口、适用人群、内容、时点、形式和验证边界，并区分偏好与实际效果。
- 主报告和附录是否合理分工，原始证据是否保留但不过度暴露。
- 未看过问卷的读者能否仅凭总览页和各章首段理解研究目的、样本、指标、主要发现和适用边界。
- 报告中的上下文补充是否只解释已有上游内容，而没有在表达阶段新增分析或提高证据强度。

### 人工审批角色

- 研究负责人
- 业务决策代表
- 涉及敏感内容时的合规、法务或数据负责人

### 通过条件

- 报告内容、证据链和限制一致。
- 报告的分享范围和归档范围获得授权。
- 后续行动的责任主体和待验证项明确。
- 课题回答与投资者教育建议均已呈现，且没有把研究建议写成已批准投教方案。
- 首次阅读抽查通过：核心结论、术语、综合指标和分群图表能够独立说明“研究了谁、在回答什么、指标是什么、发现了什么和适用于哪里”。

### 退回目标

- 证据或洞察问题：Gate 3 前。
- 表达、结构或引用问题：ResearchReport 生成阶段。

## 7. 标准审批记录

每次人工审核使用独立的 `ApprovalRecord`，至少记录：

- `metadata.artifact_id`：审批记录自身的唯一 ID。
- `gate_id` 与 `status`。
- `primary_target_ref`：本关口的主审产物及精确版本。
- `reviewed_refs`：本次决定实际查看的全部支撑产物及精确版本。
- `reviewer`、`reviewer_role` 与 `authority_basis`。
- `recorded_at`、`decided_at` 与 `decision_basis`。
- `blocking_issues`、`required_changes`、`accepted_risks` 与 `comments`。
- `attestations`：确认已查看主产物、支撑产物、重要变更且具有决定权限。
- `supersedes_approval_id`：如本记录替代旧审批时填写。
- `is_ai_approval=false`：AI 预审不得被写成正式批准。

各关口的标准审批包如下：

| Gate | `primary_target_ref` | `reviewed_refs` 至少包含 |
|---|---|---|
| Gate 1 | ResearchBrief | ResearchBrief |
| Gate 2 | ResearchPlan | ResearchPlan、全部拟执行的 InstrumentSpec、对应 ReviewResult |
| Gate 3 | InsightPackage | InsightPackage、相关 FieldworkPackage |
| Gate 4 | ResearchReport | ResearchReport、最终 InsightPackage |

审批记录只对上述产物组合的精确版本有效。`reviewed_refs` 中任一产物的内容发生变化，都必须生成新版本并重新进入相应 Gate；不得通过修改原审批记录延长批准范围。

## 8. 回溯原则

| 问题发生位置 | 默认回退位置 |
|---|---|
| 研究方向错误 | ResearchBrief |
| 方法或样本错误 | ResearchPlan |
| 题目、提纲、材料或逻辑错误 | InstrumentSpec |
| 原始数据或来源问题 | FieldworkPackage |
| 编码、统计或解释错误 | InsightPackage |
| 表达、版式或引用错误 | ResearchReport |

如果下游问题暴露了上游定义错误，必须回到最早发生错误的产物，而不是只修改报告表面。
