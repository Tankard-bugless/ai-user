# 统一术语表

本文件规定项目内术语的唯一含义。Prompt、Schema、报告、代码和答辩材料必须使用本表口径。

## 1. 规范语义链

原始业务需求 → 待支持决策 → 研究目标 → 研究问题 → 假设 → 研究方案 → 研究工具 → 原始资料 → 证据单元 → 研究发现 → 洞察 → 建议 → 业务决策

任何环节都不得跳过证据链直接生成下游结论。

## 2. 业务与研究定义

| 中文规范名 | 英文/字段建议 | 定义 | 不等于 |
|---|---|---|---|
| 原始业务需求 | Raw Demand | 需求方用自然语言提出的问题、愿望或现象描述，尚未完成研究转化 | 研究问题 |
| 待支持决策 | Supported Decision | 研究结果将帮助业务方作出的具体选择；必须说明决策主体和可选行动 | 研究建议、既定答案 |
| 研究目标 | Research Objective | 本项目需要通过研究获得何种知识，以支持待支持决策 | 宏泛愿望，如“更懂用户” |
| 研究问题 | Research Question | 研究必须用证据回答的明确问题，可以指导方法、工具和分析 | 问卷中的单道题 |
| 假设 | Hypothesis | 在收集证据前提出的可证伪解释或预期关系 | 事实、发现、洞察 |
| 研究方法 | Research Method | 获得证据的方式，如访谈、问卷、可用性测试、日记研究 | 研究工具 |
| 研究方案 | Research Plan | 对目标、人群、方法、样本、执行、分析和限制的完整安排 | 问卷或访谈提纲 |
| 分析计划 | Analysis Plan | 在收集数据前规定如何回答研究问题、使用哪些指标或编码方式 | 看到数据后的临时解释 |

## 3. 研究工具与执行定义

| 中文规范名 | 英文/字段建议 | 定义 | 规则 |
|---|---|---|---|
| 研究工具 | Instrument | 用于采集研究证据的结构化工具，包括问卷、访谈提纲、任务脚本等 | 必须关联研究问题或假设 |
| 问卷题目 | Survey Item | 问卷中可被参与者作答或阅读的最小单元 | 不等于研究问题 |
| 访谈主问题 | Interview Question | 引导参与者讲述经验、行为或判断的开放式问题 | 不应暗示期望答案 |
| 追问 | Probe | 基于参与者回答进一步获取具体事件、行为、原因或反例的问题 | 不应机械执行 |
| 甄别条件 | Screener Criterion | 用于判断候选人是否符合研究样本要求的条件 | 正式客户标签 |
| 配额 | Quota | 为保证样本覆盖而设定的项目内人数或比例目标 | 总体分布估计 |
| 测试材料 | Test Material | 在研究中向参与者展示的产品说明、概念卡片、原型、图片或链接 | 研究证据本身 |
| 学习资源 | Learning Resource | 在核心测量之后提供的可选知识入口，如 IMA 知识库链接；用于连接调研与后续学习 | 测试材料、研究证据、用户理解证明 |
| 智能发行 | Smart Distribution | 外部问卷平台对已完成设计的问卷进行发布、回收和数据导出 | 研究设计、数据分析、客户信息库 |
| AI 解释 | AI Explanation | AI 基于已审核事实生成的简短通俗说明，用于降低术语理解门槛 | 知识题标准答案、产品推荐、合规意见 |
| IMA 复核深度 | IMA Review Depth | 记录 IMA 候选内容实际被读取到什么程度：`TITLE_ONLY` 或 `CONTENT_REVIEWED` | 内容权威等级、用户是否阅读 |
| IMA 接口状态 | IMA API Status | `RESERVED_DISABLED` 表示只保留接口、不允许工作流调用；`ACTIVATED` 表示已满足跨环境读取、来源追溯、安全测试和人工批准条件 | Skill 是否安装、知识库链接是否可打开 |
| 材料理解度测试 | Material Comprehension Test | 在记录材料暴露情况后，测量参与者理解、误解和态度变化的研究模式 | 营销转化活动 |
| 预测试 | Pilot Test | 正式执行前用少量内部或目标参与者检查题意、流程、时长和技术逻辑 | 正式样本 |
| 研究参与者 | Participant | 提供问卷、访谈或测试数据的人 | 系统操作用户 |
| 样本 | Sample | 本项目实际纳入分析的参与者或记录集合 | 目标客户总体 |

## 4. 证据与分析定义

| 中文规范名 | 英文/字段建议 | 定义 | 使用要求 |
|---|---|---|---|
| 原始资料 | Source Record | 未经分析改写的答卷、逐字稿、录音、日志、观察记录或数据文件 | 保存来源、时间和版本 |
| 证据单元 | Evidence Unit | 从原始资料中提取、可定位和可复核的最小证据，如原话、答卷值或统计结果 | 必须带 source locator |
| 观察 | Observation | 研究者对单个或少量证据的描述性记录，尚未形成跨证据模式 | 不自动进入报告核心发现 |
| 研究发现 | Finding | 在本项目样本范围内，由多个证据单元支持的可描述模式、差异或问题 | 不等于因果解释 |
| 洞察 | Insight | 对发现背后的机制、意义或决策影响所作的解释，并说明替代解释和适用边界 | 不等于用户原话 |
| 建议 | Recommendation | 由洞察推导出的可考虑行动，包含预期作用、风险和待验证项 | 不等于已批准的业务决策 |
| 投资者教育建议 | Investor Education Recommendation | 建议的一种行动领域；基于本轮洞察说明优先学习缺口、项目内适用人群、内容重点、时点、候选形式、边界和效果验证 | 通用金融科普、产品宣传、个性化投资建议、已证实有效的投教方案 |
| 业务决策 | Business Decision | 有权限的业务负责人在综合研究、合规、成本和战略信息后作出的决定 | Agent 自动输出 |
| 反例 | Negative Case | 不符合主要模式的证据或参与者情况 | 不应作为噪音删除 |
| 矛盾证据 | Contradictory Evidence | 对同一主张给出不同或相反支持的证据 | 必须解释或降低置信度 |
| 研究限制 | Limitation | 对样本、方法、数据质量或结论外推范围的约束 | 通用免责声明 |
| 置信度 | Confidence | 基于证据数量、质量、独立性、三角验证和反例情况，对某项主张可靠程度的分级判断 | 证据成熟度 |

## 5. 分群、画像与标签定义

| 中文规范名 | 英文/字段建议 | 定义 | 权限边界 |
|---|---|---|---|
| 研究分群 | Research Segment | 为解释本项目内差异而形成的参与者分组 | 仅在当前研究范围内有效 |
| 候选用户画像 | Candidate Persona | 基于有限研究证据形成的行为、目标或态度模式描述 | 不得假装代表总体规模 |
| 候选研究标签 | Candidate Research Tag | 由研究产生、等待进一步验证的描述性标签建议 | 不自动写入客户档案 |
| 正式客户标签 | Official Customer Tag | 经治理规则、充分证据和授权审批后进入正式客户系统的标签 | 不由单个研究项目决定 |
| 适当性标签 | Suitability Tag | 根据法规和机构制度形成的风险承受能力、投资者分类等正式标签 | 必须与研究标签隔离 |

## 6. 问卷数据状态定义

| 中文规范名 | 英文/字段建议 | 定义 | 规则 |
|---|---|---|---|
| 题目值状态 | Item Value Status | 单道题答案在分析中的语义状态，包括实质回答、未知、不适用、不愿回答、结构性缺失和题目缺失 | 不等于整份答卷是否有效 |
| 答卷状态 | Response Status | 单份答卷的数据质量处置结果：`UNASSESSED`、`VALID`、`REVIEW_REQUIRED` 或 `EXCLUDED` | 单一可疑信号不得自动排除 |
| 答卷状态原因码 | Response Reason Code | 解释答卷为何需要复核或排除的标准代码 | 必须使用预先定义口径并保留审计记录 |
| 数据集状态 | Dataset Status | 整批数据能否进入分析的状态：`ANALYSIS_READY`、`ANALYSIS_READY_WITH_LIMITS` 或 `BLOCKED` | 必须在全部答卷完成状态解析后判定 |
| 结构性缺失 | Structural Missing | 因合法跳转或题目不适用而没有答案 | 不作为漏答或无效信号 |
| 题目缺失 | Item Missing | 本应作答但没有答案 | 依据预定义阈值评估，不自动等于整份答卷无效 |

详细判定口径以[《问卷数据有效性与输出状态》](data-validity-and-output-status.md)为准。

## 7. 系统与协作定义

| 中文规范名 | 英文/字段建议 | 定义 |
|---|---|---|
| 工作流模板 | Workflow Template | 定义一类研究如何开展的可复用流程，不包含某次项目的真实数据 |
| 项目实例 | Project Instance | 从模板创建的某一次具体研究，冻结其所使用的模板版本 |
| 阶段 | Stage | 工作流中具有明确输入、任务、输出和完成条件的单元 |
| 任务 | Task | 阶段内可执行、可分派和可记录状态的工作项 |
| 研究产物 | Artifact | Agent、人员或系统生成并用于正式交接的版本化对象 |
| Schema | Schema | 对结构化产物字段、类型、必填项和校验规则的机器可读定义 |
| 专家 Agent | Expert Agent | 在明确能力边界内进行研究判断并生成特定产物的 AI 角色 |
| 专家能力卡 | Expert Capability Spec | 定义职责、输入、判断规则、输出、质量检查、禁止事项、交接条件和测试案例的规范 |
| 研究总控 Agent | Orchestrator Agent | 根据状态和规则分派任务、检查前置条件并触发审核，不负责研究结论 |
| 工作流状态 | WorkflowState | 某次运行在一个时点的不可变控制快照，记录阶段、运行状态、有效版本、任务集合和最近迁移 |
| 任务记录 | TaskRecord | 一次可执行工作的版本化记录，冻结目标能力、输入、输出契约、权限、状态、重试和失败处理 |
| 交接记录 | HandoffRecord | 两个任务或责任主体之间的最小上下文交接，记录精确引用、开放字段、排除数据、验收条件和返回路径 |
| 适配器 | Adapter | 将核心产物转换为外部平台需要的格式，或把外部结果转换回核心格式 |
| 审核关口 | Review Gate | 流程中必须由授权人员确认后才能继续的状态节点 |
| 审核结果 | Review Result | 对某个目标产物进行方法、逻辑或合规检查后形成的问题清单和建议结论 |
| 审批记录 | Approval Record | 人工对一次 Gate 所审查的主产物和支撑产物精确版本组合作出的批准、退回、拒绝或取消记录 |
| 研究资产 | Research Asset | 经归档、具有来源和版本信息、可供后续项目检索或复用的研究文件或模板 |

## 8. 核心产物命名

下表中的英文名是文件名、Schema、Agent 输入输出和流程状态中使用的唯一规范名。中文名用于展示，不得另造同义产物名。

| 中文规范名 | 英文规范名 | 定义 | 主要内容 |
|---|---|---|---|
| 研究任务书 | ResearchBrief | 将原始业务需求转换为可研究问题的首个正式产物 | 待支持决策、研究目标、研究问题、假设、目标人群、范围与约束 |
| 研究方案 | ResearchPlan | 说明如何取得足以回答研究问题的证据 | 方法、样本与招募、执行方式、分析计划、质量标准、风险与限制 |
| 研究工具规格 | InstrumentSpec | 平台无关的问卷、访谈提纲或测试任务定义 | 题目或问题、追问、选项、逻辑、材料、变量、值语义、有效性规则、研究问题映射 |
| 审核结果 | ReviewResult | 对指定产物版本执行方法、逻辑、表达或合规检查后形成的结构化结果 | 问题、严重度、定位、修改建议、预审结论 |
| 研究执行包 | FieldworkPackage | 汇集实际执行过程和原始资料的版本化容器，本身不是更高等级的研究证据 | Source Record、样本完成情况、执行日志、答卷状态、数据集状态、数据质量与脱敏说明 |
| 洞察包 | InsightPackage | 保存从证据单元到发现、洞察和建议的完整分析链 | Evidence Unit、Finding、Insight、Recommendation、反例、限制、置信度 |
| 研究报告 | ResearchReport | 面向需求方表达经审核结果的正式交付物 | 摘要、方法、发现、证据、洞察、建议、限制与附录 |
| 审批记录 | ApprovalRecord | 授权人员对某个审核包的精确版本组合在审核关口作出的不可覆盖记录 | Gate、主审产物、全部已审版本、决定、意见、审批人、时间与失效规则 |

## 9. 禁止使用的模糊表述

| 模糊表述 | 必须改写为 |
|---|---|
| 用户需求 | 研究目标、用户表达、研究发现或待验证假设中的一种 |
| 用户认为 | 明确参与者范围、证据类型和来源 |
| 大多数用户 | 给出本样本中的分子、分母和筛选条件；定性研究避免总体化表达 |
| 事实 | 原始资料、证据单元或研究发现中的一种 |
| 结论 | 明确是 Finding、Insight、Recommendation 还是 Business Decision |
| 标签 | 明确是候选研究标签、正式客户标签还是适当性标签 |
| AI分析 | 明确使用的输入、规则、模型版本、输出和人工审核状态 |
| 用户理解了材料 | 给出理解度指标、题目或行为证据 |
| 无效问卷 | 明确是哪个答卷状态、原因码和执行规则；不得凭主观印象删除 |

## 10. 参与方命名

- 需求方：提出业务问题并使用研究结果的内部人员。
- 研究人员：设计、执行、分析并对研究质量负责的人员。
- 审核人员：对指定 Gate 具有确认权限的人员。
- 研究参与者：接受问卷、访谈或测试的外部或内部对象。
- 客户：机构业务语境中的客户实体；不得与所有研究参与者自动等同。
