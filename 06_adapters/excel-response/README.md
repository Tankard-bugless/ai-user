# Excel 答卷回传适配器

本适配器定义问卷结束后如何把业务方回传的 `.xlsx` 文件接入研究工作流。Excel 是问卷数据的正式交接载体；腾讯问卷或其他平台只负责智能发行、回收和导出，不决定分析口径。

## 责任边界

- `InstrumentSpec` 是题目、选项、变量、特殊值、跳转和有效性规则的唯一权威来源。
- Excel 是本次实际答卷的原始数据文件，进入 FieldworkPackage 后登记为 Source Record。
- 平台中的在线统计图、自动结论和用户画像不直接进入证据链。
- 不要求通过腾讯问卷 API 读取答案；业务方导出并回传 Excel 即可。
- 分析专家只读取完成字段映射、脱敏和质量状态处理后的数据，不直接在原始工作簿上改值。

## 最小回传内容

业务方只需提供：

1. 平台导出的原始 `.xlsx` 文件。
2. 一句话说明答卷来源和投放范围。
3. 导出时间；如未说明，则以文件接收时间登记并标注限制。

其余导入、映射和质量检查由工作流完成，不要求业务方手工整理模板。

## 导入后形成的四层数据

| 层级 | 内容 | 规则 |
|---|---|---|
| 原始工作簿 | 业务方回传的 Excel | 只读冻结，不覆盖、不清洗 |
| 字段映射 | Excel 列名 → `item_id` → `variable_name` | 以 InstrumentSpec 为准，无法映射时暂停分析 |
| 规范化答卷表 | 一行一份答卷、一个变量一列 | 统一多选、缺失值、跳转空缺和编码 |
| 质量结果 | 单份答卷状态、原因码和整体数据集状态 | 执行问卷设计阶段已经确定的规则 |

## 字段映射口径

1. 优先从列名中的稳定题号读取 `C0`、`S1`、`Q1` 等 `item_id`。
2. 题目文字只能辅助核对，不能单独作为长期主键；平台可能调整标点、换行或截断标题。
3. 每个导出字段必须映射到 InstrumentSpec 的 `item_id` 和 `variable_name`。平台时间戳等辅助字段单独登记，不伪装成研究变量。
4. 多选题可以在原始文件中表现为单列分隔值或多列布尔值；规范化后必须保留选项编码，并记录转换规则。
5. 跳转造成的空白标为 `STRUCTURAL_MISSING`，适用但未作答标为 `ITEM_MISSING`，不得混为同一个空值。
6. 如导出题目版本与 Gate 2 批准版本不一致，数据集进入 `BLOCKED`，不能边猜字段边写报告。

## 隐私与最小数据

导入时默认移除或隔离以下平台字段：昵称、头像、OpenID、IP、精确位置、设备标识、User-Agent、联系方式和其他直接标识。

当前养老目标基金案例只保留：

- 题目作答。
- 生成的匿名答卷 ID。
- 判断答卷质量所必需的时间与技术字段。
- 已预定义的年龄段等分析维度。

原始名单、账户信息和平台身份不得与匿名答卷合并后交给分析专家。

## 数据有效性输出

每份答卷先进入 `UNASSESSED`，再按照 InstrumentSpec 的既定规则转为：

- `VALID`
- `REVIEW_REQUIRED`
- `EXCLUDED`

整体数据集输出：

- `ANALYSIS_READY`
- `ANALYSIS_READY_WITH_LIMITS`
- `BLOCKED`

只有前两种状态可以交给 CAP-05。知识题答错、选择“不确定”、年龄不愿回答或开放题留空，不会被单独判为无效答卷。

## 分析交接

Excel 导入完成后，工作流向 CAP-05 交付：

- 冻结的原始工作簿引用。
- InstrumentSpec 与平台字段映射。
- 规范化答卷数据。
- 纳入、复核、排除和原因码汇总。
- 数据集状态、已知限制和实际投放来源说明。

CAP-05 由此生成 Evidence Unit、Finding、Insight 和 Recommendation；CAP-06 再生成研究报告及独立的投资者教育建议板块。

## 当前案例

养老目标基金购买者问卷已经发出。回传 Excel 后，先核对版本、题号、选项和值语义，再执行答卷有效性规则；不再把腾讯问卷的在线统计或答案 API 作为必要依赖。
